# 관내여비 콕검 v0.2.12

에듀파인 관내여비 자료(`.xls`, `.xlsx`)를 브라우저에서 읽어 근무지와 출장지의 **보행 왕복거리와 2km 이내 여부를 확인**하는 학교 행정실 업무 보조 도구입니다.

## v0.2.12 변경사항

- `위치 확인 필요`에서 출장지를 수동으로 확정하면 해당 출장지의 왕복거리를 즉시 자동 계산
- 동일 경로의 23시간 이내 캐시가 있으면 새 TMAP 호출 없이 저장된 거리 결과를 즉시 적용
- TMAP 일일 안전한도 때문에 자동 계산을 실행할 수 없는 경우 위치 확정은 유지하고 거리 계산만 보류
- 위치 확정 뒤 `거리 계산 전` 상태로 남아 사용자가 다시 계산 버튼을 눌러야 했던 흐름 수정

## v0.2.11 변경사항

- 결과표의 `위치 확인 필요` 배지를 눌러 해당 출장지의 장소 선택 화면을 바로 열 수 있도록 연결
- 띄어쓰기·기호를 제외한 장소명이 정확히 일치하는 검색 결과가 하나면, 주차장 등 유사 결과가 함께 있어도 본 장소를 자동 확정하도록 보강
- `서울`/`서울특별시`처럼 주소의 시·도 표기가 달라도 같은 권역으로 판단하도록 자동 선택 지역 비교 로직 보정
- 에듀파인 학교회계 안내 경로에 `조회 기간 설정` 단계 추가

## v0.2.10 변경사항

- Upstash Redis 기반 **전역 TMAP 경로조회 카운터** 추가
- 화면에 `오늘 사용량 / 1,000회`와 이번 점검 최대 예상 조회량 표시
- 800회부터 경고, 900회를 자체 안전한도로 설정해 신규 거리계산 차단
- 서버에서도 Redis 원자적 예약 후 TMAP을 호출해 동시 사용자 상황에서도 900회 안전한도 보호
- 사용량 저장소를 확인할 수 없으면 신규 거리계산을 실행하지 않는 fail-closed 방식 적용
- TMAP 거리 결과 브라우저 캐시를 **23시간 이내**로 자동 만료
- Upstash에는 날짜별 경로조회 횟수만 저장하며 출장자명·파일명·출장지 등 업무자료는 저장하지 않음
- `STORAGE_URL` / `STORAGE_TOKEN` 및 일반 Upstash 환경변수명을 모두 지원

## v0.2.9 변경사항

- 메인 문구를 `관내출장, 거리부터 콕 검토해요.`로 정리
- 메인 문구와 작업 단계명을 학교 행정실에서 바로 이해할 수 있는 업무 언어로 정리
- 작업 단계를 `파일 가져오기 → 근무지 설정 → 거리점검 → 결과 확인`으로 통일
- 파일 업로드 전에 학교회계 에듀파인 경로를 기본 노출
  - 학교회계 → 지출관리 → 지출지원 → 출장여비 → 출장여비(관내) → [출력] → [엑셀 저장]
- 교특회계 경로는 접어서 제공
- 파일을 수정하거나 열을 삭제할 필요가 없다는 안내 추가
- 상단 `도움말` 추가
- 도움말에 에듀파인 경로, 사용 순서, 결과 해석, 개인정보 처리, 오류 대응 안내 추가
- 업로드 영역에 개인정보 처리 요약 상시 노출
- 파일을 올리기 전에도 브라우저 저장정보를 지울 수 있는 `저장정보 삭제` 제공
- 근무지 설정 영역에 `저장정보 모두 삭제` 제공
- 장소 검색 요청을 브라우저 → 앱 서버 구간에서 POST body 방식으로 변경
- 거리 계산 요청에서 장소명을 보내지 않고 출발·도착 좌표만 전달하도록 축소
- 결과 엑셀의 표기와 파일명도 `거리점검`으로 통일

## v0.2.8 이전 주요 변경

- 개인정보 보호 안내를 업로드 영역에 강조 표시
- 푸터에 `제작 senvip`과 GitHub 링크 추가
- 파일 업로드 영역에 학교회계·교특회계 엑셀 저장 경로 안내 추가
- 원본 출장지와 지도 검색어를 분리
- `1층`, `3층 회의실`, `대강당`, `시청각실` 등 건물 내부 위치를 지도 검색 시 자동 제외
- `본관`, `별관` 같은 건물 구분은 보존
- 도로명주소의 숫자와 번지는 그대로 유지
- 화면과 결과 엑셀에 원본 출장지와 정리된 지도 검색어를 함께 보존
- 장소 자동 확정 시 정리된 지도 검색어를 기준으로 일치 여부 판단
- 출장자·날짜별 지급 검토 작업대, 이동수단 선택, 검토 메모, 완료·보류 처리 제거
- 여러 출장지의 위치 확인과 거리 계산 중심 흐름 복구
- 출장별 결과표를 `출장일 / 출장자 / 출장지·목적 / 왕복거리 / 2km 판정 / 확인사항` 6열로 단순화
- PC 결과표의 가로 스크롤 제거, 모바일 결과 행 카드형 전환
- 왕복 2km 이내는 `이동수단 확인 필요`로 안내
- 위치 미확인, 거리 계산 실패, 경계 구간 자동 안내
- 상단 요약 숫자를 눌러 결과 필터 적용

> 이 앱은 여비 지급액을 확정하지 않습니다. 거리 결과는 검토를 돕기 위한 확인자료이며 최종 지급 여부는 관련 지침과 기관 기준을 확인해 판단해야 합니다.

## 개인정보 처리

### 브라우저에서 처리하는 정보

- 사용자가 선택한 에듀파인 엑셀 원본
- 출장자명
- 출장목적
- 여비금액 등 파일에 포함된 출장 자료

원본 엑셀 파일과 위 데이터는 서버에 업로드하지 않고 현재 브라우저에서 읽고 처리합니다.

### 지도 서비스로 전달하는 정보

- 장소 검색: 사용자가 입력하거나 원본 출장지에서 정리한 **지도 검색용 장소명**
- 거리 계산: **출발·도착 좌표**

출장자명, 출장목적, 여비금액은 지도 검색 또는 거리 계산 요청에 포함하지 않습니다.

### 브라우저에 저장될 수 있는 정보

다음 사용에서 다시 확인하는 수고를 줄이기 위해 `localStorage`에 아래 정보가 저장될 수 있습니다.

- 근무지 이름·주소·좌표
- 사용자가 확인한 출장지 이름·주소·좌표
- 계산한 경로 거리와 지도 표시용 경로 캐시

TMAP API로 얻은 위치·경로 데이터는 24시간 이상 재사용하지 않도록 **23시간 이내에서 자동 만료**합니다.

화면의 **저장정보 삭제 / 저장정보 모두 삭제**를 누르면 위 저장정보를 한 번에 삭제합니다. 현재 불러온 엑셀의 출장자명·출장목적 등은 `localStorage`에 저장하지 않습니다.

### TMAP 사용량 카운터

TMAP 무료 사용량을 보호하기 위해 Upstash Redis에는 아래 값만 저장합니다.

- 한국시간 기준 날짜
- 해당 날짜의 TMAP 보행 경로조회 누적 횟수

출장자명, 파일명, 출장지, 좌표, 출장목적, 여비금액은 사용량 카운터에 저장하지 않습니다.

## 에듀파인 파일 경로

### 학교회계

학교회계 → 지출관리 → 지출지원 → 출장여비 → 출장여비(관내) → 조회 기간 설정 → [출력] → [엑셀 저장]

### 교특회계

재정사업관리 → 사업재정관리 → 재무관리 → 관내여비관리 → 엑셀 저장

## TMAP API 설정

1. SK Open API에서 앱을 생성합니다.
2. 해당 앱에 TMAP 상품의 무료 요금제를 연결합니다.
3. 발급받은 App Key를 Vercel 환경변수에 등록합니다.

```text
TMAP_APP_KEY=발급받은_앱키
```

4. Vercel에서 다시 배포합니다.

## TMAP 사용량 보호 저장소 설정

Vercel Marketplace에서 **Upstash for Redis**를 이 프로젝트에 연결합니다. 현재 Vercel 연결 화면에서 Custom Prefix를 `STORAGE`로 두었다면 코드가 다음 환경변수를 자동 인식합니다.

```text
STORAGE_URL
STORAGE_TOKEN
```

다음 일반 이름도 함께 지원합니다.

```text
KV_REST_API_URL / KV_REST_API_TOKEN
UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN
```

환경변수 값은 브라우저로 노출하지 않고 Vercel 서버 함수에서만 사용합니다. Upstash 연결 후에는 **Redeploy**가 필요합니다.

### 사용량 보호 기준

- TMAP 경로안내 무료 제공량: 1,000회/일
- 콕검 경고: 800회부터
- 콕검 자체 안전한도: 900회
- 보행 왕복거리 1곳 계산: 경로조회 2회

`/api/tmap-route`는 TMAP을 호출하기 전에 Redis에서 필요한 2회를 원자적으로 예약합니다. 900회를 넘길 수 있는 요청은 서버에서 차단합니다. 사용량 저장소가 연결되지 않았거나 일시적으로 확인되지 않는 경우에도 신규 거리계산을 진행하지 않습니다.

## Vercel 배포

1. 프로젝트 파일을 GitHub 저장소에 올립니다.
2. Vercel에서 저장소를 가져옵니다.
3. `TMAP_APP_KEY`를 `Production and Preview` 환경에 등록합니다.
4. Upstash for Redis를 프로젝트에 연결하고 Production/Preview 환경변수가 생성됐는지 확인합니다.
5. Deploy 또는 Redeploy를 실행합니다.

## 테스트

```bash
npm test
npm run build
```

포함된 비식별 테스트 파일은 `.xls`와 `.xlsx` 모두 동일하게 다음 결과로 파싱됩니다.

- 관내출장 4건
- 출장자 4명
- 출장지 3곳

기존 관내여비 내역 파일은 `.xls`와 `.xlsx` 모두 **관내출장 30건 · 출장자 16명 · 출장지 17곳**으로 동일하게 확인했습니다. 추가로 제공된 `관내여비대상목록.xlsx`도 **관내출장 54건 · 출장자 15명 · 출장지 28곳**으로 정상 인식했습니다. 실제 파일은 개인정보 보호를 위해 ZIP에 포함하지 않습니다.
